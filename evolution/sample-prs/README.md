# Sample Pull Requests from Fido

This folder preserves real pull-request descriptions from the development of [Your Friend Fido](https://github.com/kevinjmireles/yff-web). The purpose is to show how the development process evolved in practice rather than presenting only the finished methodology.

GitHub issues and pull requests share one numbering sequence, so round numbers such as #100, #200, #300, #400, and #500 are not necessarily pull requests. The samples below use actual PRs that clearly represent different stages of process maturity.

2. [PR #469 — review findings become reusable engineering standards](pr-0469.md)
3. [PR #555 — audit-first work, explicit exclusions, architecture checks, and grading](pr-0555.md)

## What to compare

Look for the evolution in:

- problem definition;
- approved scope and exclusions;
- acceptance criteria;
- test and validation evidence;
- failure-mode and risk review;
- documentation requirements;
- reuse and parallel-path checks;
- review rounds and corrections;
- Builder handoffs;
- self-grading and reviewer grading;
- explicit follow-up tracking.

The early PR was not bad. It already contained useful context, testing notes, and operational follow-ups. The later PRs show what happened as recurring failures were converted into templates, rules, reviewer responsibilities, and merge gates.
