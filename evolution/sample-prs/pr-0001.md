## Original PR description

> **Why**
> - Supabase reserves the `SUPABASE_*` prefix for secrets; we now read `SB_URL` and `SB_SERVICE_ROLE_KEY`.
> - Harden Edge Functions for production (rate limiting, validation, CORS, optional shared secret).
>
> **What changed**
> - Shared env loader reads `SB_URL` / `SB_SERVICE_ROLE_KEY` (fallback to `SUPABASE_*`).
> - All Edge Functions use `getEnv()` (no direct `Deno.env.get("SUPABASE_*")`).
> - Security: IP-based rate limiting (DB RPC), CORS via `CORS_ORIGINS`, optional `x-edge-secret`.
> - Functions implemented: `profile-address`, `subscriptions-toggle`, `unsubscribe`.
> - Civic API: `divisionsByAddress` with retry + 503 fallback.
> - Docs updated: `edge-functions.md`, handoff “Now vs Later”, env notes.
>
> **Testing**
> - `profile-address` POST returns `{ ok:true, data:{ zipcode, ocd_ids } }` and upserts `profiles` + `subscriptions`.
> - `subscriptions-toggle` switches `unsubscribed_at` and returns status.
> - `unsubscribe` verifies HMAC token and is idempotent.
> - Rate limiter returns `429 RATE_LIMITED` after burst.
>
> **Ops/Follow-ups**
> - Secrets set in Supabase: `SB_URL`, `SB_SERVICE_ROLE_KEY`, `CIVIC_API_KEY`, `UNSUB_SECRET` (+ optional `CORS_ORIGINS`, `EDGE_SHARED_SECRET`).
> - (Later) Separate PRs for `ingest-sendgrid` and `log-delivery`.
>
> **Checklist**
> - [ ] Reviewed env changes in `supabase/functions/_shared/env.ts`
> - [ ] No `.env*` files committed
> - [ ] Docs updated

## What this shows

This early PR already contains several good instincts: a clear reason for the change, a concise list of implementation changes, testing notes, security considerations, documentation, and operational follow-ups.

It also shows how much of the process still depended on the author and reviewer filling in the gaps:

- the three-item checklist remained unchecked;
- there was no linked issue or observable acceptance-criteria section;
- test commands and results were not recorded;
- risks were discussed implicitly rather than through a standard risk gate;
- there was no independent reviewer grade or confidence level;
- no explicit reuse, duplication, or parallel-path assessment appeared;
- the PR was very large, touching 47 files in one change.

The lesson is not that the first PR was poor. It is that useful engineering judgment existed, but had not yet been converted into a repeatable system that made the same questions unavoidable on every PR.
