# Process Evolution

The current workflow did not appear fully formed. It evolved through repeated failures, frustrating handoffs, deployment problems, duplicated systems, weak reviews, and missing documentation.

This section shows how the process changed over time rather than presenting the current system as if it had always existed.

## Evolution studies

- [Prompt Evolution](prompt-evolution.md)
- [Issue Evolution](issue-evolution.md)
- [Pull Request Evolution](pr-evolution.md)
- [Repository Instructions Evolution](claude-md-evolution.md)
- [Testing Evolution](testing-evolution.md)
- [Documentation Evolution](documentation-evolution.md)

Each study asks:

1. What did the process look like then?
2. What failed or became painful?
3. What changed?
4. Why is the current approach better?
5. What can another team copy?

## Evidence over mythology

The goal is not to claim a perfect methodology. The goal is to show the evidence of improvement: early issues, early pull requests, later pull requests, changing templates, growing test coverage, and the development rules added after recurring failures.

Representative production pull requests are archived in [evolution/sample-prs](sample-prs/README.md).
