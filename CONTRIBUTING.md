# Contributing

This repository documents failure patterns, lessons, tools, and processes discovered while building real software with AI.

Contributions are welcome from publishers, product leaders, developers, and non-programmers who have encountered a repeatable AI-assisted development problem and introduced a useful way to prevent it.

## A useful contribution

The strongest contributions are grounded in a real experience and answer five questions:

1. **What failed or became difficult?**
2. **Why did it happen?**
3. **What system, rule, test, or process did you introduce?**
4. **How did it help?**
5. **What can another person reuse?**

Evidence is encouraged. This may include a public issue, pull request, test, incident description, before-and-after workflow, or other artifact that readers can inspect.

## What to avoid

Please avoid:

- generic AI advice without a real example;
- promotional content;
- claims that one model, tool, or workflow is universally best;
- duplicating an existing lesson when the current document can be extended;
- sharing private, confidential, or security-sensitive information.

## How to contribute

Open an issue describing the proposed lesson before drafting a large document. The issue should identify the failure pattern, the existing material it relates to, and whether the proposal extends an existing lesson or requires a new one.

This follows one of the repository's core rules:

> Before creating something new, first determine whether an existing system or document should be extended.

Small corrections, broken links, clearer examples, and evidence-backed improvements are also welcome.
